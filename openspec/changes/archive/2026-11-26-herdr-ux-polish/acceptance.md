# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Connected parent Crew precedes the far-right chevron, with no child count in either fold state.
- One, two and three children share a centred stem and final corner, with badges aligned to the coordinator name at both requested zooms.
- Legacy combined, placement-v1 project and mixed populations retain exact same-machine native membership and project names without overriding user renames.
- Every child retains native numbering, selection and compact membership; dragging any member moves the whole acknowledged block with stale-membership refusal.
- Cold coordinator inventory uses one top-left Loading below tabs and withholds partial successes until first reads settle.
- Warm return and background updates retain the prior list with native header activity, no body Loading or Stale text, and in-place replacement on completion.
- Actionable repository notices remain visible while incomplete totals stay truthful and quiet cooldown recovery retries without a new event.
- Retained presentation grants no GitHub-read or worker-navigation authority; existing history, fold, reveal, scroll and mounted-safety bounds remain.
