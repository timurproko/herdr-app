# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Crew kind captions align left without truncation, and options read Plain, Delivery, Gate with stable hover geometry.
- Pointer-origin selection, Escape and outside dismissal retire row reveal; intentional keyboard editing remains operable.
- Dashed Delivery kinds information shows the exact aligned explanation on hover or focus without a click action or option tooltips.
- Native execution contention queues with capped pre-start retries while confirmed projects, badges and true fix counts remain visible.
- Supported coordinator-owned kind acknowledgements apply normally, while older ownership refusals stay short and neutral without replaying uncertain writes.
- Git stages and verdicts use centred equal boxes measured through two-digit rounds; longer numbers grow only themselves without title reservations or tooltips.
- Coordinator-containing Agents groups precede other groups through a stable partition without changing folds, counts, selection or drag handlers.
