# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Automatic reset is off by default per machine, with no reset types selected and no inherited consent for newly discovered types.
- Only explicitly checked usable types with proven scope and a fresh exact-machine account reading at 1 percent remaining or less can spend.
- The open active desktop monitors its selected machine at the existing cadence even without a summary or dialog, with no closed-app daemon.
- Durable account admission prevents duplicate or cascading spends across windows, selected machines, restarts and uncertain outcomes.
- Captured account-only reconciliation updates dialog quotas, reset inventory and pinned sidebar values without Refresh all or unrelated changes.
- Confirmed automatic spending uses one existing-style success toast identifying its captured target, while manual reset success stays silent.
- Failed validation preserves provider Retry-After, and failed or obsolete follow-ups cannot fabricate a refill or revive disabled collection.
