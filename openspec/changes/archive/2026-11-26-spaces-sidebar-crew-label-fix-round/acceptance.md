# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Completed nonlive reports retain read-only history and live ambiguous membership cannot gain historical or worker authority.
- Workers read their own repository and pages despite absent or unverified seeds; branch abandonment and retained rate credit cannot create unlimited root retries.
- One failed Open or Closed page does not suppress its unread sibling, and each tab retains only its own actionable failure.
- Stage chips use tight plain palette text without emoji or outline, show supplied Build rounds, and preserve guarded focus, PR opening and finding hover.
- Managed stages reserve no title width; only a live unlabelled fallback robot can shorten the title's right boundary.
- Tab, sidebar and keyboard selection own the pin without entry motion; collapse retains it, lone headers disappear and section counts exclude it while tab totals remain full.
- Existing sidebar columns, shared rename presentation, captured targets and native input ownership remain intact with no live runtime modifications.
