# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Git feedback shares the repository header's text anchor and 28px single-line row while long diagnostics grow below their first line.
- Empty repository headers and zero counts are absent; actionable headerless notices survive saved folds and continuation batches.
- Spaces shows lowercase crew without changing terminal Crew badges or connected-child ordering.
- Crew current round 1 shows Build through planning and approval; current round 2 shows Build 2 without an extra increment.
- Git's full-width accent line and cold dot breathe by opacity only over 2400ms, with static dim reduced-motion feedback.
- Stage verdicts share guarded build-owner pointer and keyboard navigation without tooltips or fallback GitHub actions.
- Agent entry publishes one resolved layout or last-good content with actionable failed-read feedback; same-terminal footer changes replace or clear the pin.
- Missing linked PRs release admission, saved folds cannot hide empty feedback, and raced detail snapshots retain rows silently with bounded retry.
