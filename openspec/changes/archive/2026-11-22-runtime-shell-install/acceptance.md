# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Full deploy owns the four shell files and publishes a deterministic content revision after script replacements.
- Bash resolves sibling runtime files at source time and preserves prompt status, existing hooks and interactive terminal guards.
- Installed export writes the existing four private snapshot classes without checkout imports or live-state changes.
- Shell-only deployment and validated journal recovery need no Desktop and preserve non-shell ownership and preference bytes.
- Current guidance names standalone source paths and installed entrypoints; native screenshot output stays in checkout artifacts.
- Only disposable fixtures were used; live installation, profile wiring and remote rollout remain separate authorized steps.
