# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Repository headers appear only for eligible rows or scoped read notices in the selected tab, without changing totals or history bounds.
- Empty settled tabs use ordinary Git wording, while folded sections and notice-only sections avoid false empty states.
- Hidden-tab repositories retain saved folds and remain eligible choices in the single pinned enrollment footer.
- Enrollment cards match ordinary Git height, padding, icon size, gaps and vertical centres with only a trailing chevron added.
- Status-bar account geometry and native popup behavior remain unchanged, with render-phase focus and notification guards retained.
