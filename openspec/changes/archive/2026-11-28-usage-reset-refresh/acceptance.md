# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Reset follow-up collects only the captured account and preserves unrelated quotas, machine caches, pins and account selection.
- A slow pre-reset collector no longer exhausts the reset refresh wait before its existing loading lease expires.
- Authoritative results repaint the dialog and mounted sidebar through their shared cache without a manual refresh or periodic tick.
- Failed reads retain existing unavailable feedback, and obsolete enable generations cannot revive reset follow-up work.
- Existing confirmation and silent success presentation remain unchanged, with no new messages, controls or timers.
