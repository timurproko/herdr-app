# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Attachment listing uses the documented default filter, and card facts omit unnecessary nested-resource options.
- Rejected reads name the HTTP status and a short safe reason without forwarding raw provider text or credentials.
- Data commands share a monotonic 60-second budget from before authority acquisition and cap each request at 20 seconds.
- Windows ACL checks receive only remaining time, retain fail-closed verification and cannot silently renew the command budget.
- Expired reads start no follow-up, publish no partial image and leave uncertain writes unreplayed.
