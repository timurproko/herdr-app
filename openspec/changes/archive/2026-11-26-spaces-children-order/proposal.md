# Proposal

## Why

The project-space preference exposes routine background progress as machine status, and connected children cannot be arranged independently. Coordinator Git sections also use alphabetical order instead of the user's child-space order.

## What Changes

- Keep Separate space per project a plain saved on/off switch, optionally disabled during bounded application; show only concise machine-named failures after an unsuccessful attempt, never routine checking, pending or success lines.
- Distinguish transitional Pending from stalled application with synthetic lifecycle/transport cases, fixing any reproduced stalled continuation without weakening uncertain-setter serialization.
- Drag connected children only among their own siblings; dragging the coordinator continues moving its whole block. Persist through existing native space ordering, preserving truthful shortcut numbers, selection, compact order and connectors.
- Order coordinator Git repository sections by matching child-space order. Match canonical task PR repositories to verified live task membership in exact connected native spaces, not project names or folder guesses. A repository associated with several children uses its earliest uniquely associated child; a child holding several repositories supplies no unique match. Unmatched sections follow in their existing relative order.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `workspace-experience`: Quiet global preference application and independently reorderable connected siblings while preserving coordinator block movement.
- `plugin-integrations`: Coordinator repository sections track matching connected child order without changing Git loading, counts or PR labels.

## Impact

Crew worker-space policy/contribution, the existing Spaces reorder adapter and acknowledgement controller, the generic read-only task-context seam and Git section ordering. Reuse existing row/toggle, drag preview/marker and native space.move operations; no native changes, Core document writes, Crew installation or new service. Update focused regressions and relevant project documentation. Changes to Git are restricted to section order and its metadata/projection, not concurrent loading/counter or stage-label work.
