# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- A requested current Custom check uses native 300 ms request maintenance, 3000 ms expiry and disabled confirmation markup in the same action slot.
- Update, Checking, Updating, failed and unknown states retain their existing labels, descriptions and action guards.
- The compact More popup Settings entry shows the same six-pixel accent circle for native or Custom availability.
- Existing footer and Settings navigation predicates remain unchanged, with no speculative redraw, polling or parallel availability mechanism added.
- A read-only capture command records selected persisted facts, installed-source fingerprints and existing desktop screenshots without live-home writes.
