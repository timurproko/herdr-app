# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Settings Updates has four sibling Herdr rows with herdr-app-plugins directly below herdr-app-custom and no separate Plugins section.
- Successful complete checks show local checked-at time, while unknown or failed evidence cannot confirm currency or renew that time.
- Check now is read-only, and Update keeps existing local-first sequential actions, named failures and uncertain-write safeguards within one status area.
- Retired discovery owners cannot strand row actions past lease expiry; the existing feedback cadence redraws expiry without adding a timer.
- Existing notification dots, native update rows and explanation remain unchanged, with targeted row, controller, feedback and marker regressions passing.
