# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Primary and secondary GitHub rate refusals retain loaded rows, totals, pins and pages without adding error UI.
- Cold refused reads keep standard Loading, share the cooldown and allow one explicit manual retry without refusal spam.
- Authentication, permission, network, timeout, abnormal-exit and malformed-response failures keep actionable notices.
- Repository batches preserve healthy aliases in partial GraphQL replies, share compatible in-flight facts and reuse final history and unchanged checks.
- Cooldown recovery reads the currently selected tab and retains its loaded depth without loading a hidden refused tab.
- Events and enrollment retain main lifecycle behavior with no two-second debounce, pending-demand transfer, inactive-window pause or deferred enrollment timer.
- Effective Git routing changes invalidate canonical identity, including a gh-resolved-only default change.
- Existing relay deployments need no change; cached final coordinator facts wait for contrary evidence or a new runtime session.
