# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Coordinator lists reveal ten presentation items initially and append near the bottom without page controls or scroll-triggered GitHub inventory reads.
- Revealed coordinator lists build only viewport-near rows with exact-height spacers while retaining intrinsic-width and immutable-label caches.
- Both Git lists reuse Spaces and Agents scroll metrics and passive 40px edge fades without render-time notifications or focus allocation.
- Coordinator safety reads exclude overscan, folded and off-window rows and reject obsolete replies after scroll or tab changes while retaining normal cadence and routing.
- Whole-inventory totals, folded sections, ordinary pinned and older rows, stable row geometry and the enrollment footer outside the scroller remain intact.
- The 100-row scroll regression retains the existing 10000-operation and 1200-element ceilings after every row is revealed.
