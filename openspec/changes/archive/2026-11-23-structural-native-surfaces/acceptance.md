# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Palette and feedback use proven current stock and structural capability checks without release or reviewed-whole-file allowlists.
- Custom palette retains native history, command discovery, clone dispatch and dynamic light-dark-layout theme choices while routing Custom actions.
- Custom feedback retains native controllers, validation and added sibling actions alongside compact attachments, drafts, JSON disclosure and sent presentation.
- Immutable helper graphs and atomic entrypoint activation retain raw originals and journaled recovery, refusing personal conflicts and unsafe restoration.
- Deploy, startup and doctor distinguish concrete optional incompatibilities from hard ownership or recovery errors without creating automatic opt-ins.
- Installed app files remain unchanged; live UI validation and deployment require separate authorization.
