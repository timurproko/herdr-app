# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Cached worker sections and coordinator returns display compatible rows and counts immediately without body Loading or a blank frame.
- Direct space entry preserves section ordering without creating a pin, reordering rows or starting move-to-top animation.
- Existing native header activity covers background refresh and accepted rows and totals replace the retained presentation coherently.
- Task-derived counts remain visibly incomplete for repository totals and each seeded tab demands its own authoritative page.
- Stage-chip and fallback robot clicks from an unpinned worker use the existing controller with one focus and native selection acknowledgement.
- Machine, repository, source and enable generations reject incompatible cached facts and obsolete replies without cached action authority.
- Main Git headers omit repository labels and repository-page shortcuts while section identity, verification diagnostics and PR row menus remain.
