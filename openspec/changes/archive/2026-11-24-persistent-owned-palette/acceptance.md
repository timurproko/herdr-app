# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Custom opens its owned palette from Ctrl+Shift+P and the status-bar button, preserving the native catalog and Custom search, scroll, rename and close behavior.
- Full installation and mounted startup checks repair stock-reset user bindings with ownership, bounded retries and visible failure diagnostics on each desktop.
- Capability checks support 0.1.17, 0.1.18 and capable newer hosts without using reviewed-version membership or native palette bytes as permission.
- Palette retirement preserves current or unknown native stock, feedback and recovery evidence while refusing personal conflicts and tolerating either stop-gap landing order.
- Native app.palette calls, other layouts and Core-only shell deployment remain native and no live app deployment, restart or upstream-sync activation is performed.
