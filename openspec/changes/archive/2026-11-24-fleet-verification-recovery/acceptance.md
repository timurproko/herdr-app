# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Failed and discarded verification records retain sanitized reason, time and generation without replacing newer binding facts or extending action freshness.
- The local fleet log stays within 128 lines and 64 KiB, suppresses unchanged reason episodes and never records raw process output or credentials.
- Existing Git verification feedback exposes the relevant failure while unverified candidates gain no attachment, PR inventory or worker authority.
- Existing Spaces lifecycle callbacks service 2, 5 and repeated 10-second recovery deadlines for every retryable reason without a second scheduler or overlapping status reads.
- Startup and mod replacement preserve recovery deadlines and display identity, while expired leases and obsolete completions cannot block or resurrect bindings.
- Enabling attaches after successful verification while Settings remains open; disabling immediately restores independent presentation and stops recovery.
