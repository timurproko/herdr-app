# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Checks retain their full icon and count through two-digit totals at 280, 320, 360 and 480px widths and 75 to 200 percent zoom without changing optional-data anchors.
- Task fractions and compact relative times remain whole, with full hover values; metadata cells never paint a lone ellipsis.
- Shown pending checks without confirmed enrollment refresh after 45 seconds through the existing queue, retaining prior values and backing off failures and rate limits.
- Settled, hidden, disabled, offline and enrolled rows start no fallback reads; completion events and coalesced follow-ups replace loaded checks without stale targeted-read overwrites.
