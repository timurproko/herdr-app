# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Feedback originals match unchanged pinned 0.1.16 and 0.1.17 source, including explicit LF and Windows CRLF bytes with release commits and digests.
- The reviewed 0.1.17 palette retains native dynamic light-dark-layout theme choices alongside all existing Custom presentation and command routes.
- Reviewed 0.1.16 and legacy palette originals remain supported without replacing their native theme choices with another release's catalog.
- Unknown or ambiguous native bytes skip only that optional patch with an advisory and leave targets, helpers, opt-ins and backups unchanged.
- Reviewed upgrades retain earlier raw backups and restore current stock; personal conflicts, corrupt records and concurrent edits remain failures.
- Automatic refresh repairs prior opt-ins only, without enabling another patch or changing native binaries, terminals or sessions.
