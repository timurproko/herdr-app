# Custom — Herdr customizations

Your mods, theme and behavior extensions, **separate from the native Herdr application**.
The layout shown in both native and custom Settings is **Custom**.
This standalone source checkout may live anywhere. With Node.js 20+, run build
and deployment from this checkout; deploy installs into `HERDR_APP_HOME` or
`~/.config/herdr-app` by default, not the checkout's parent. Authored source stays
separate from installed/runtime files.

Read [development guidance](docs/DEVELOPMENT.md) and the [architecture decision guide](docs/ARCHITECTURE.md)
before development. No command here builds Herdr or herdr-core.

## Ownership

| Location | Owner / purpose |
|---|---|
| This project's `src/`, `tools/`, `tests/`, `customization.json` | Your canonical source |
| `<Herdr home>/preferences/` | Private durable snapshots (per-host profiles, palette, layout preferences); version in private dotfiles, not here |
| `dist/` | Generated customization packages; ignored by version control |
| `<Herdr home>/mods/custom-*/`, `layouts/Custom.json`, `themes/Custom.json` | Installed customization output; do not edit directly |
| `<Herdr home>/.customizations/runtime/` | Self-contained deployed workers and shell integration; no source-checkout dependency |
| `<Herdr home>/.customizations/` | Local ownership records, preference projection, patch opt-ins and rollback journals; never sync |
| `<Herdr home>/.customizations/recovery/` | Archived Herdr recovery copies; retained outside the live `mods/` scanner |
| `<Herdr home>/settings.json`, `keys.json` | Native global settings/shortcuts, not source in this repository |
| Stock mods/layouts, `frame/`, SDK declarations, generated `AGENTS.md` | Herdr-owned; regenerated by Herdr |
| `shared.json`, `data/`, `.state/`, window/view files | Host runtime state; never sync or edit wholesale |

Herdr discovers mods only as direct `mods/<name>/mod.json` children, so installed
mods cannot be nested under one directory. The `custom-*` prefix is the ownership
boundary; unprefixed `confirm`, `prompt`, and `toast` are stock again.

`customization.json` explicitly maps feature entrypoints, assets and shared helpers.
The build additionally injects the documented Herdr facade/identity files into each
sandboxed mod. A helper is written once, then packaged into each mod that needs it.
The copies are necessary
runtime packaging, not independently maintained implementations. Feature IDs stay
stable independently of the layout's display name.

### Herdr facade

All 17 private mods and both retained frame compatibility patches import `./host.js`;
only `src/integration/herdr/host.js` imports the native `herdr` module. It preserves
native call arity, normalizes collection/object boundaries, produces actionable
missing-API errors, and resolves commands/API aliases through
`src/integration/herdr/compatibility.js`.

After a Herdr update, run `npm run check:host-api`. It compares the reviewed
profile with the regenerated `herdr.d.ts`, the live command catalog, and direct
imports. If an API or command was renamed, update one profile/adapter rather than
every feature. Data-shape changes may require one normalizer in `host.js`. Native
patch source can still need a reviewed rebase when Herdr changes its private UI
implementation—the facade reduces public API churn but cannot make copied native
frames structurally version-independent. Shell selection now uses native `tab.new`
and is labelled **Open new tab in…**; it never replaces the existing shell. Profile
startup is separate and retains a read-only core space-existence check; see
[shell tabs and profile startup](docs/ARCHITECTURE.md#shell-tabs-and-profile-startup).

## Moving tabs between spaces

Right-click a tab → **Move to…** → choose another space on the **same machine**
(this computer or a connected machine such as `pc2`). Destination names and colored
number badges match the sidebar. The tab keeps its running terminals and splits;
moving does not change their working directories. After the window confirms the
move, the destination sidebar icon and label pop up and settle back, without
any background flash or hover-style highlight. The compact rail pops its badge;
a folded machine pops its header label/icon instead. This is visual feedback
only: no automatic selection, unfolding or scrolling. Failed,
unacknowledged and metadata-only repair operations do not animate an arrival.
You stay in the source space: the moved tab is not opened, and a final-tab move
leaves a Start page rather than closing that space. Ordinary close preferences are unchanged. There are no menu
item tooltips or loading text. Left/Escape returns from the destination list;
Enter selects. Move to uses a leading outline right-chevron aligned with Back's
left-chevron. Unavailable/empty explanations wrap instead of being ellipsized,
with scrolling for long messages. Compatibility refusals identify the unmet method/command, minimum version,
generation or document-shape requirement. If terminal labels need attention after
a committed move, reopen that tab's submenu and choose **Repair move metadata**.

This feature is a user-authorized, narrowly scoped Core-document compatibility
adapter, not a native rebuild. It requires **App 0.1.15+ / Core 0.1.19+**, protocol
generation **1**, the required methods/commands and a recognized document shape.
Newer unreviewed App/Core versions work when those checks pass; review-list
membership is not runtime permission. Unknown structural shapes still fail closed. Moving between different machines,
floating panes, Start pages and detected space-bound mod props are unsupported.
Remote identity verification uses the existing Node.js/hc on that machine; it does
not require installing the App or a companion there. A timeout can mean
an unknown outcome: check the tab's actual location before retrying. See
[the architectural contract and concurrency limits](docs/TAB-MOVE-ADR.md).

`npm run check:tab-move` automates pinned release-source comparison and synthetic
move/menu regressions. Host/deploy checks automatically run that audit for an
unknown App version; it reports the review delta independently of runtime eligibility.
The optional source audit can still report `needs-review` for a capable newer host.
See [commands, provenance and limits](docs/TAB-MOVE-COMPATIBILITY.md).

core privileges are **not** part of `npm test` and require separate approval.

- Edit source, never `dist/` or installed mods.
- Add new source/output mappings to `customization.json`; relative imports must resolve in the emitted package.
- Shared design changes belong in `src/ui/`; palette/layout defaults belong in `src/appearance/`.
- Keep service operations out of appearance code. Settings may compose feature UIs without owning their worker implementations.
- No hot-reload watcher, daemon, desktop restart or terminal-input injection is installed.

## Optional sidebar plugins

Plugins declare their Settings UI (requirements, settings, list sections, pages) and one
shared renderer draws it; see [docs/PLUGIN-UI.md](docs/PLUGIN-UI.md).

Enable **Files** and **Git** independently in **Settings → Plugins**. Both default
to enabled so existing installations keep their panels.

- Both off: the right-sidebar toggle disappears and the sidebar is hidden.
- Files only: the sidebar contains just the file browser, with no dropdown.
- Git only: the sidebar contains just Git, with no dropdown.
- Both on: the header dropdown switches between Files and Git.

Disabling a panel stops new local/SSH filesystem, Git and GitHub reads from that
plugin. Already-started requests may finish but cannot start follow-up work while
disabled. Existing file-viewer tabs and confirmed in-flight recycle operations are
not closed or cancelled. Pins, expanded folders, plugin settings and native layout
preferences are not deleted. A disabled pinned view projects onto an enabled panel;
re-enabling restores the remembered view unless you deliberately choose another.
Native `workspace.panels` preferences remain untouched.

The implementations and assets live in `src/plugins/files/mod/` and
`src/plugins/git/mod/`. Their `plugin.js` declarations contribute sidebar metadata;
`panel.json` owns each independent mod's packaging/shared dependencies. Other mods
receive lightweight declarations, not another panel's implementation. The generic
registry, sidebar title/switcher, and pin controller compose the enabled panels;
Git has no Files asset or code dependency. Stable `custom-files`, `custom-changes`
and stack IDs preserve existing tabs/layouts. This remains a private customization,
not a Herdr native change.

## Run a profile as the Firstmate coordinator

In **Settings → Profiles**, add or edit an ordinary agent profile and turn on **Run as
Firstmate**. The command stays the literal `a1` (or its full path) with its literal
arguments; the role is profile metadata bound to the profile's stable key, so renaming
or reordering keeps it and unticking removes it. A small `Firstmate` pill marks such
profiles in the list, the **+** menu and the Start page. Turning the role on or off
affects future launches only.

Launching a marked profile is a required moment, not an optional tweak: the Tabs
controller asks the Firstmate plugin's `profile.role.firstmate` gate to prepare the
launch, and any refusal ends the job with the reason (plugin off, folder not chosen,
profile on a different machine than the configured clone, not the full A1 executable,
machine disconnected, folder not a repository root, a live coordinator already labelled
for that home, or an unreadable clone revision). A refused launch never falls back to
an ordinary A1 session. When prepared, the agent starts with the clone as its working
directory and carries `custom.firstmate.home/path/revision[/dirty]` and
`custom.profile.role` labels from birth; nothing is typed into the terminal, installed,
pulled, fixed or unlocked. The gate only reads (`hc machine ls`, label-filtered
`hc ls`, `git rev-parse`/`status`). Firstmate's own session lock remains the
authority once the agent runs; the plugin's live-owner check is a duplicate-click guard,
not an ownership claim, and the labels report what started, not that the coordinator is
ready. Ordinary profiles produce exactly the same launch request as before.

The role is a portable preference (`firstmate: true|false` on the profile) and is
exported/imported with other profile settings; launch jobs, labels and tokens are not.

## Profile editing and removal

Cancel or Escape from a profile editor returns to the same list scroll position.
The native list stays mounted behind an independently scrolling editor, so a short
form cannot reset the list to the top. Custom-profile removal asks only **Remove
this profile?** beside that row, with **Cancel / Remove**. Confirmation buttons do
not arm or complete row dragging; canceling leaves the profile and order untouched.
Existing sessions remain unaffected by profile editing or removal.

## Optional Usage plugin

**Settings → Plugins → Usage** controls the complete quota feature: the Usage
dialog, sidebar summary, sidebar shortcut, Usage settings page and collectors.
It defaults to enabled to preserve existing installations. Disabling it hides
those entry points, reclaims the summary's space, closes an already-open Usage
dialog without stealing focus, and stops new local/SSH collection work. A live
Settings page falls back to Plugins if its plugin is disabled.

Per-machine check/summary/percentage/Automatic settings, pinned quotas, footer
placement and last reports are preserved. Re-enabling restores them; disabled
in-flight reads cannot launch a collector, and results from a prior enable
generation cannot overwrite newer reports. An already-running collector may
finish; no process or terminal is killed. Existing per-machine **Check usage**
switches remain separate from the global plugin switch.

The complete implementation is owned by `src/plugins/usage/`: `mod/` contains the
dialog, settings renderer, store and collector; `model.js` owns quota models;
`sidebar.js` owns summary layout reconciliation. Settings delegates via a generated
plugin-page adapter and sidebar chrome emits a generic lifecycle event. Claude
session account switching remains independent of optional Usage statistics.

## Refresh feedback and Git

Refresh icons dim/disable and rotate while their request runs. Manual clicks
and Settings loads in Core, Profiles and Terminals stay visibly busy for at
least **600 ms** to avoid a flash, including returning to an already-cached
section. Each new section entry restarts that minimum. Refreshed data and
errors are applied immediately, and longer requests spin until completion.
The visual minimum is scoped to the clicked control and its machine/folder or
Settings section, so switching context does not inherit another refresh.
Refresh controls and the Usage settings gear have no hover tooltips;
accessibility labels remain available.
Git's event-driven CI line sits immediately below its header and applies to
all PRs, not just the pinned block. Rotation and line motion use native animation,
not JavaScript frame timers. This applies to Settings, Files, file-pane
reloads, Git and Usage (including each requested provider). Files has no polling
or folder watcher: it refreshes when opened, when the machine or working folder
changes, or when you click Refresh. Switching agents, tabs or spaces in the same
machine/folder reuses the loaded tree and any pending reads without a loading flash. Expanding a folder re-reads it, collapsing one
re-reads its parent, and moving the pointer into the panel re-reads shown folders
older than 4 seconds. Folders read within the last second are skipped, and all
folders due at once are listed in one PowerShell/sh request (one round trip for a
remote machine). Hidden Files panels do no new scans; opening
an unexpanded folder still loads its children on demand. Only a manual refresh
rotates the Files icon, and same-folder agent switches preserve expanded folders. Usage
disables all refresh actions while its selected machine's single collector is
busy, including the minimum 600ms feedback interval. Only the initiating icon
rotates: a provider refresh animates that block, a global refresh animates only
the header. Unrelated settings and close controls remain available. Git's Refresh is
hidden when the current folder is not a repository; Pin and Close remain available.

Hover any file or folder row for half a second to see its complete name in a
tooltip, including when the label is truncated. This works at every tree depth.

Files keeps the outlined icon for empty folders and uses a filled icon for folders
with content, whether collapsed or expanded. The shallow check includes hidden
items and `.git`; unreadable folders keep the outlined fallback. Opening/context
changes and manual refresh update the icons without recursively loading the tree.

Clicking a file first activates an already-open viewer for that **full path in the
current space**, including a settled tab, instead of creating a duplicate. The
existing editor and scroll position are retained; it does not reload the file.
Windows paths ignore case and slash direction; POSIX paths remain case-sensitive.
Legacy basename or renamed viewers can use their known in-memory full path.
Same-named files in other folders/spaces or on other machines are not reused.
Tabs with several file panes are ambiguous in the public host API and open a new
viewer rather than risk focusing the wrong file. New files still open in native
read-only tabs; rapid repeated clicks are suppressed while creation is pending,
with a three-second retry lease if the host does not acknowledge it. Right-click
**Open...** keeps its external-app/plugin behavior.

Right-click a file or folder → **Delete...** for a compact modal showing only the
filename beneath one sentence: “Deleting this file moves it to the recycle bin.”
Folder confirmations also mention their contents. No full path or machine label
is displayed; the target machine stays captured internally. **Delete** (or Enter) confirms; Cancel, Escape and Close do
nothing. It moves the item (including a folder's contents) to **that machine's
recycle bin/trash**, where the login user can restore it. SSH operations use the
remote login user's bin, not this computer's bin or a downloaded local copy.
Windows uses a guarded Shell recycle operation on fixed local volumes (not
network/removable drives); Linux needs `gio` or `trash-cli`; macOS uses Foundation's
Trash API. Paths are literal/quoted and directory links are not traversed.
**There is no permanent-delete fallback.** An unavailable bin, unsupported volume,
permission problem or disconnected machine reports an error without retrying.
The shown tree refreshes after success; existing viewer tabs stay open. The success
toast says “File successfully deleted” (or “Folder successfully deleted”) with only
the filename beneath it.
After an uncertain result, check both the original folder and that machine's bin.
A confirmation expires after five minutes or if another context menu
replaces its target; reopen the menu to try again. No terminal input, native
change, remote companion or persistent deletion queue is involved.

Files and Git headers have **Refresh · Pin · Close** tools in that order, using
24px targets, matching 12px Refresh glyphs, 14px Pin/Close glyphs and the existing hover reveal. Pin remembers **Files or
Git and open/closed state for the current tab**, separate from the shared sidebar
choice used by unpinned tabs. Returning through tab clicks, keys or agent navigation
restores that tab's choice. While pinned, switching the panel or opening/closing it
updates only that tab; other tabs keep their normal shared choice. Unpin returns
to the shared choice. The pin is **unpressed by default** and uses the exact same
angled icon as Usage in both states. When pinned, it has Usage's pressed fill,
border and foreground treatment, rather than switching to a crossed-out icon.
Width remains native/global. Pins are client-local, qualified-tab runtime state, not portable
preferences; no Core document, terminal or agent is changed. Reconciliation yields
out of render and waits for native acknowledgements rather than polling/replaying
layout commands.

The Git header no longer has a separate PR-link tool. **Right-click its header**
for a menu titled with the captured **owner/repository** name, followed by
**Code...**, **Pull requests...** and **Actions...**. These open the repository
root, pull-request list and workflow runs page respectively, in this computer's
browser. The menu captures the clicked repository, supports arrow keys,
Enter/Escape and does no Git/GitHub reads of its own. It is unavailable until a
GitHub URL is known or outside a Git repository. Individual PR rows keep their
existing Open... / Copy path menu. Like Files' folder label, the Git header shows
the short repository name beside its title and the full GitHub URL on hover.
The tooltip belongs only to the label, not the Refresh/Pin/Close tools rail.
There is no stale folder fallback while repository metadata is unavailable.
Git shows only **Open** and **Closed** pull requests. Both load **10 PRs initially**
and fetch the next 10 near the bottom of the scrolling list, using GitHub cursors
rather than redownloading earlier pages. Each tab keeps its own rows and cursor;
counts still show GitHub's full totals. A **Load 10 more** control also supports
explicit loading and retry after a page error. Busy requests are single-flight;
failed pages preserve existing rows, and the end of the list stops fetching.
Expanded lists are retained across webhook refreshes; manual Refresh or a
machine/folder change starts again at 10. Same-folder agent/tab/space switches
retain repository metadata, counts, rows, pagination and in-flight GitHub requests;
only the agent-specific active PR link changes (A1 and Claude Code read their selected session footer).
The current pin stays steady until that read resolves; an unchanged PR never
unpins/re-pins. Ordinary selection changes use a native 120ms opacity ease.
Clicking a list PR's robot opens the agent tab **immediately**. The panel retains
the original row slots while the destination footer/selection resolves, including
when a repository refresh replaces the underlying rows. Once confirmed, native
320ms motion moves the clicked PR into the pinned slot, returns the former pin
to the list and slides any affected intermediate rows. The real layout commits
only after motion settles, using the latest refreshed PR facts. There is no
optimistic pin change or delayed navigation. Geometry uses measured heights and
current scroll/zoom; pagination and scroll remain intact. Geometry lives as long
as the native element IDs, not the repository data: resolving a Git root cancels
pending motion but must not discard size measurements that the host only emits
when dimensions change. Only one arming and
one cleanup callback run (no JavaScript frame loop). A bounded 3-second wait
prevents an unavailable destination from freezing the old presentation.
A clicked destination already verified as the same GitHub repository retains
rows even when its worktree/folder needs a fresh Git-root lookup; old-folder
requests are invalidated first. Unrelated machine/folder or Open/Closed changes,
scrolling, a mismatching destination or a newer selection cancel retention/motion
without undoing navigation. Unmeasured rows and cross-repository switches safely
use the normal pin reveal. Ordinary terminals keep the same list and
use the existing explicit-tab/branch matching when available. An explicitly linked active PR older
than the first page gets one targeted lookup so it can still be pinned, without
fetching intermediate pages. The former Changes tab, diff
preview and commit form are removed; a remembered Changes selection opens Open.
Check counts use the newest Actions run per workflow, excluding obsolete jobs
from older runs on the same commit. In-progress reruns stay pending rather than
showing an earlier attempt's result. Untouched body checklists show a muted
checklist icon and **2 tasks** (or **1 task**), not **0 of 2 tasks**. Partial
progress keeps its ring; completed lists keep their purple check and done label.
All PR rows, including coordinator/fleet rows and both Open/Closed tabs, omit the
Owner badge. Below the number/author/time line, metadata starts at the same left
edge with **tasks · checks · assigned GitHub labels**, omitting absent groups.
Labels are compact pills in their exact GitHub colours and names (including emoji),
with contrasting text. Multiple/long labels stay in a bounded single-height strip:
pill text truncates, and hovering the pills or metadata exposes complete names,
including clipped labels. No labels means no placeholder or extra separator;
label refreshes never add extra row lines or horizontal overflow. Metadata separators,
including the number/author dot, share a clearly visible muted 3px round shape,
vertically centred beside text/icons with equal 6px spacing on both sides.
Git follows the selected terminal's live shell-reported directory (including remote
Bash and PowerShell), not its launch folder. Changing locations immediately clears
the old repository and counts; late Git/GitHub replies cannot restore them. A
non-repository home folder shows **Not a git repository**. In the selected
Open/Closed list, the active PR is always pinned above the scrollable rows with a
divider underneath and a 2px theme-accent rail on the left, even when it is the only
PR. The rail overlays the outer gutter without shifting content or the hover
area. It is not duplicated below and has no special background; all PRs use the
normal neutral hover. With no matching active PR, the whole list scrolls normally.
For A1 and Claude Code, the panel
reads the selected terminal's current footer PR badge through the read-only `hc read`
API (no history, input injection or transcript-wide PR searches). Claude's `PR #…`
permission strip must appear immediately below its model/context usage row; a
conversation mention alone never links a PR. This session link
wins over tab names and shell branches: an agent may work in an internal worktree while
its parent shell still reports `develop`. When the footer is unavailable, an explicitly
named PR tab (`906`, `#906` or `PR #906`) takes precedence over branch matching.
Automatic positional tab names are not PR links, and peek/replacement terminals
cannot borrow the underlying tab's link. Otherwise the active terminal's branch
is matched to the PR head branch. Selection follows terminal/worktree switches;
branch/footer changes in the same terminal are picked up by the existing 10-second
local context refresh (or manual Refresh), independently of webhook-driven CI. With neither an explicit link nor a matching branch,
rows stay unselected.

CI updates are **webhook-driven**, for **pinned and unpinned PRs**. Under
**Settings → Plugins → Git**, explicitly use **Install → Login → Configure**
when relay setup or a notice-format upgrade is needed, then expand **Repositories**.
Choose the GitHub **Account**, open **Add repo**, select repositories in its search
picker and confirm **Add**. Only that explicit Add changes webhooks; searching,
selecting alone or Cancel does not. The main list retains last-confirmed enrollment;

this list. The picker reads paginated active admin repositories, not local clones;
choosing an account does not switch the global CLI login. Partial successes stay
saved and failures require an explicit retry. Setup privately installs pinned
Cloudflare tools, opens browser authorization and configures the relay/keys/URL.
No wizard, secret copying or URL pasting is required. Configure starts immediately;
Install all cannot trigger cloud changes or enroll webhooks. The configured URL is
read-only, and picker selections are per-view, never preferences or replay jobs.
See [Git webhook setup](docs/GIT-WEBHOOKS.md). Credentials stay local and are never
preference exports; customization deployment itself provisions no account/service.

Enabled Git shares one authenticated native WebSocket from mounted non-footer
chrome, with a short owner lease across duplicate mounts/windows. Relevant events
refresh all loaded Open/Closed pages and an explicitly linked older PR; expanded
lists retain their depth and renewed cursors. Bursts coalesce, reconnect/open catches
up, and stale replies cannot update another machine/repository. Hiding Git or
selecting another repository stops hidden panel reads, not update notifications.
Disabling Git or closing its chrome owner closes transport; another mounted owner
can take over. Failed reads retain the last good status. There is **no
periodic CI polling or polling fallback**; unconfigured/offline panels show a
compact bottom info card **Set up Git in Settings** only when global setup is
missing. With setup ready, an unenrolled Git repository instead shows **Add this repo in Settings**. Enabled repos and non-Git agents have
no prompt; transport reconnects and agent switches do not flash setup messages.
Switching repositories immediately hides the old **Add this repo in Settings**
card. It reappears only if the destination is confirmed unconfigured, never while
its repository or enrollment is still being checked.
Manual Refresh remains available. Its **Settings** link opens Git's prerequisites
directly for missing setup. **Add this repo in Settings** instead opens Requirements
collapsed and Repositories expanded, with the captured **owner/repository** prefilled
in search. It only filters the list: choose the appropriate account if needed,
open Add repo, select the repository and confirm Add yourself. The header **‹ Plugins** button returns
to the full catalog. Transport backoff and local agent discovery are
separate from CI checking.

When any loaded PR has running checks (including unpinned or draft PRs), an
event-driven refresh starts one subtle 1px accent sweep **immediately below the Git
header**, above Open/Closed. It eases left-to-right over **2.4 seconds**, then stops.
Two one-shot phase callbacks sequence native motion, not JavaScript frames or a
continuous loop. The pinned block and its bottom divider stay still.

An open PR with GitHub's explicit `CONFLICTING` mergeability replaces its normal
PR icon with a **red outlined circle and X**, using the same stroke style as PR icons. Hover that icon for **Merge conflicts**.
Unknown mergeability and failing/blocked checks are not conflicts. Closed/merged
PRs keep their usual icons. Push events also refresh facts after base-branch changes.

PRs with a related live agent show a separate white/foreground robot beside
the title, matching the Agents sidebar. The original colored PR icon stays.
The robot uses the usual rounded inset-icon hover tint, distinct from the
row's hover, and no tooltip; clicking opens
the agent's existing tab without opening GitHub.
The rest of the row still opens GitHub. Right-click any PR (pinned or scrolling,
Open or Closed) for the same menu as Files: **Open...**, a divider, then **Copy path**.

URL and shows the standard **Path copied** success toast. Escape dismisses, Enter

Links include background tabs/spaces and
remote agents, verified using the panel's canonical `gh repo view` lookup

A1's or Claude Code's footer, an explicitly named PR tab, or the live branch (in that order).

## Ask the PR’s agent to fix failed CI

**Settings → Plugins → Git → Settings** contains **Auto-fix failed CI**
(off by default), **Send when agent is** (a checkbox multi-select dropdown), and an
editable **Message**. Idle/Done are selected by default; Error and Working are
opt-in, and selecting none stops delivery. Blocked is excluded. Working input may
queue; sends are never forced. `{url}` expands to the
PR URL; `{runUrl}` expands to the failed Actions run URL. Default:
“Analyze failed CI run {runUrl} for {url}. Fix the cause; Push.”

**Turn on Auto-fix failed CI.** It automatically provisions Core-side monitoring
on this computer and connected SSH machines, reusing Git's existing repository
selections. No separate background setup, status/Check section or machine/scope
controls are needed. Each worker polls its local Core roughly once a minute and uses
that host's own gh login. Closing Herdr leaves the worker active; pc2 does not depend
on the main PC staying on or connected over SSH. This is a limited-user Windows
task: the host must remain awake/online and its user signed in. No native Core patch,

## Terminal copy feedback

On Windows, Custom shows its own centered terminal-font popup, **Copied N chars to
clipboard**, for best-effort native terminal mouse copy-on-select—not the standard
notification. It sits at the bottom center of the terminal area in the source tab,
with white terminal-font text, the theme's popover background and border, and the
original rounded box and fade/slide animation. It stays for two seconds before
fading out; another settled copy updates it and renews its lifetime.

Missing window facts during cold startup do not disable the observer: it starts
when those facts arrive. Turning native `copy_on_select` off stops this feedback;
turning it back on resumes it. The observer reads the local clipboard directly,
without subprocesses, and leaves text, selection and terminals unchanged. Each
settled selection produces at most one popup, including same-text inference.

Herdr exposes selection changes, not copy completion or mouse release. Feedback
therefore uses a short selection-settle delay and bounded clipboard checks; a held
drag or unrelated clipboard activity can still be mistaken for a copy. Explicit or
repeated shortcut copies with unchanged selections cannot be detected reliably
without an upstream copy-success capability. This is not an every-copy guarantee.

## Usage request limits

Healthy usage accounts are checked at most every 10 minutes while the window is active.
The widget checks automatically on its minute timer, when the window regains focus,
and when the selected machine or its Check usage switch changes; opening Usage is
not required. An account fetched locally or by another machine within those 10 minutes
is reused, not requested again. Reuse and provider-only refreshes never extend other
accounts' original expiry; a manual Refresh always asks the provider. When a provider answers 429, that
account is not requested again until its Retry-After time (60 seconds when none is
given, at most an hour), including by manual Refresh; the card says when the next
check is possible and keeps showing the last known usage. Unavailable providers
show a quiet **Refresh required** status, not technical login/token/API warnings;
collector failures use the same short message. Click **Refresh required** or the
provider's refresh icon to retry. Claude refresh updates all saved Claude accounts
on that machine, including accounts hidden by its picker, without refreshing other
providers or changing the selected account/pins. The sidebar widget never offers a
refresh action: missing/error/stuck values show **---** in their pinned positions,
and clicking the widget always opens Usage. Routine automatic refreshes keep the
current percentages visible and replace them directly when new values arrive,
without a placeholder flash or a **Refresh required** prompt. Healthy quotas keep their original compact, natural alignment. The widget keeps
each value's native-measured width when replacing it with `---`, without adding
oversized columns or moving neighboring quotas. Every pinned quota keeps its own provider icon,
including multiple quotas from the same provider; captions remain stable across
missing reports. Ten minutes controls collection/reuse, not an immediate visual
expiry: good values survive the next minute tick and an active refresh for up to
135 seconds. A missed tick, failed request or timed-out collector shows **---**;
timeouts release refresh controls, and retrying a failure keeps the placeholder
until collection actually succeeds.

## Status bar items reveal

rule: an item hides only when what it shows changed or it moved (something to its

to right once the bar stops changing: 60ms after the last change, then 90ms apart.

from automatic quota reset times. The available count uses the same text style as

## Preferences versus generated files

Changing Padding records intent in `.customizations/layout-preferences.json` and
projects it into the native layout. Deploy preserves allowed personal look fields
and refuses structural conflicts. It no longer treats a 7px padding choice as a
corrupt installation. Theme picks and native click state remain Herdr's concern.

```powershell
npm run preferences:export
# Restore only after YOU close Herdr Desktop; leave core/terminals running:
npm run preferences:import
npm run deploy
```

The exporter validates palette ownership and writes **credential-filtered private
backups**, not anonymized or public-safe exports. Account-derived usage pins and
arbitrary plugin settings are preserved and may contain account identities,
infrastructure identifiers, relay URLs or personal paths. Filtering is not a
guarantee that a snapshot is free of secrets or personal information. **Never commit
personal snapshots to this public repository**, even if the exporter accepts them.

Export/import use `<Herdr home>/preferences/`, where home is `HERDR_APP_HOME` or
`~/.config/herdr-app`, matching deploy. Host files are `<lowercase-hostname>.json`.
The same private directory holds `layout.json` (layout overrides), `palette.json`
(picker metadata) and `theme.json` (native-schema palette). These three files are
personal portable backups, not shipped defaults; authored defaults stay in
`src/appearance/`. Build/deploy need none of these snapshots. Host files never
overwrite a different computer's profiles. Global settings/shortcuts remain native
files. Version the snapshots in private yadm/dotfiles that track the Herdr home,
not this checkout. Full deploy installs the export-only Node entrypoint
`<Herdr home>/.customizations/runtime/scripts/export-preferences.mjs`, accepting
`export <home>` with an explicit home. It produces the same four snapshot classes
without source imports, validates layout overrides against the recorded installed
layout base, and rejects import/extra arguments. The source export command shares
that operation, with an authored-base fallback only for source-only usage.
Private pre-commit hooks may call this installed exporter; deploy does not install
hooks, and no pull hook imports state or restarts the desktop. Reconcile a palette
conflict rather than overwriting it. See [the exact export command](docs/COMMANDS.md#portable-preferences).

### Existing snapshots: manual relocation

Tools do not read, migrate or delete old checkout host snapshots. Move a desired
`<old checkout>/preferences/<hostname>.json` yourself into
`<Herdr home>/preferences/<hostname>.json`; missing host files leave local profiles
unchanged. The maintainer's existing snapshot must move from
**`~/.config/herdr-app/customizations/preferences/pc.json`** to
**`~/.config/herdr-app/preferences/pc.json`** (or
**`$HERDR_APP_HOME/preferences/pc.json`** when using a nondefault home).

Before updating a checkout that still tracks `preferences/layout.json`,
`palette.json` and `theme.json`, preserve any wanted personal copies in that same
home preference directory; this version removes their public source copies.
Reconcile existing destination files manually, without blindly overwriting them.
No automatic migration runs, and the checkout's entire `preferences/` directory
remains ignored to protect any leftover personal files.

## Update all machines

**Settings → Updates → herdr-app-custom** is one row beside Herdr and herdr-core,
showing a short installed revision and **Check now** or **Update**. Update uses the
existing all-machine command through an independent, finite runner: full deploy
on this desktop and shell deploy on eligible peers. Its desktop source is only
`~/.local/share/herdr-app` (created on first Update if absent), never the developer
checkout or a crew worktree. Checks compare published main every **2–3 minutes** with jitter while
Custom is mounted and raise the existing Custom dots; they never deploy or probe
peers. Each desktop checks independently, including one without relay setup.
Startup, window activation after two minutes idle and delayed timers after sleep
catch up automatically. Offline failures persist jittered retry delays of roughly
5, 10, 20 and then at most 30 minutes, reset on success; Check now still bypasses
the cache under the same single-flight lease. No public network-return event is
assumed: timer retry and supported activation signals are the fallback.

For near-immediate discovery, the updater independently subscribes to the shared
Git relay while Git is enabled: only `timurproko/herdr-app` main pushes or closed,
merged PRs targeting main invalidate its cache. A 300 ms debounce and 15-second
automatic rate floor coalesce hints into a bounded authoritative main check;
events never decide availability or install anything. Git disabled, missing relay
setup, legacy notices or no repository enrollment leave **updater-owned polling**
working independently. After merge, install the observer on each desktop, explicitly
upgrade the relay with Configure, and enroll the repository through Account → Add
repo → select → Add. Do not sync private keys. See [setup and limits](docs/GIT-WEBHOOKS.md#customization-update-discovery). Unknown/changed revision evidence is shown honestly as revision unknown.

The latest status, result and log live under the selected Herdr home's
`.customizations/`: `update-status.json`, `deploy-all-result.json`,
`update-check.json` and `update.log`. An update started from Updates keeps that
page visible through mod replacement while its job is active or for two minutes
after completion. Custom's Settings openers attach a fresh per-opening identity
in supported overlay props; native/backdrop dismissal or a Desktop restart cannot
reuse a prior opening's hint, even when Herdr reuses its native overlay ID.
Ordinary navigation is not remembered. A new opening honors its requested page or
starts on Look; unqualified direct mod opens also keep that default rather than
trusting an overlay ID. The update-only resume hint is runtime state, never a
portable preference.
Shared launch feedback keeps the row on Updating before the detached runner's
receipt arrives; a lost receipt becomes outcome unknown, not stale Up to date.
Reload/closing Settings does not cancel or repeat an update. Peer skips/failures retain the successful desktop revision and
show one short matching-details warning (`update.log` for Settings runs,
`deploy-all-result.json` for ordinary CLI runs without a captured log); desktop
failure names the cause and documented
manual rollback. Missing results/deadlines say outcome unknown and block replay
while the prior process/lock is unresolved. Ordinary CLI failures also retain
their cause/recovery/details line after checking; a CLI installer timeout's
durable result blocks another Settings update even without a Settings lock. There is no per-machine UI, news,
rollback button, automatic rollback, daemon, scheduler or job history. See
[first installation and real-app checks](docs/COMMANDS.md#trying-the-row-after-merge).
The label is defined once in `src/shared/customization-update-model.js`.

Run `npm run deploy:all` from this checkout on the desktop. It requires **clean main**
(including untracked files), fetches origin and refuses the entire run if ahead of
or diverged from origin/main. It never stashes, resets or switches branches.
It fast-forwards selected local source and runs the existing full `npm run deploy`,
including the host compatibility check, build, ownership checks and backup.
Checkout HEAD equality alone does not prove the installed files are current.

Use `npm run deploy:all -- --dry-run` to preview (still fetches; no fast-forward,
build or install), `--only local,pc2` to select machines, or `--skip-local` to omit
the desktop deploy. The source safety gate always runs. The final per-machine
summary includes deployed/current/skipped/failed, source commit and any printed
backup ID. Failures exit non-zero; stated skips alone do not. See
[command details](docs/COMMANDS.md#watched-all-machine-deployment).

Each peer needs a configured/reachable Herdr Core and Git, Node 20+ and npm on
**Core's PATH**, plus a clean main clone of this repository at
`~/.local/share/herdr-app`. Full desktop deployments are skipped: run their own
full deploy there. To set up a new peer once, **on that machine**, clone
`https://github.com/timurproko/herdr-app.git` to that path and run
`npm run deploy:shell -- "$HOME/.config/herdr-app"` from the clone. This explicit
first installation and shell-profile wiring are manual steps; see
[remote setup](docs/COMMANDS.md#one-time-new-peer-setup) and
[installed shell reporting](#installed-shell-reporting). deploy:all never clones,
installs tools or repairs checkouts. Its output table alone is not
installed Git provenance; the latest result sidecar additionally ties a successful
desktop commit to its installed ownership-manifest digest. It never restarts live
shells or agents.

## Installed shell reporting

On a Core-only host without Desktop/Custom, run `npm run deploy:shell` from this
standalone checkout (Node 20+); an optional home follows `--`. It installs only the
four shell files using the same lock, ownership, conflicts and journals as full
deploy, preserving all non-shell output and preference bytes. It never enables a
layout or invokes native checks/patches. A later full deploy shares that ownership.
`npm run rollback:shell -- <backup-id> [home]` restores only a verified shell-only
journal without Desktop, refusing mixed journals, newer records and later edits.
Ordinary deploy/deploy:shell never contacts peers. `deploy:all` explicitly authorizes
updates to eligible existing peer checkouts; new-peer setup remains manual.

Deploy owns `<Herdr home>/.customizations/runtime/shell/` containing
`bash-cwd-loader.sh`, `bash-cwd.sh`, `powershell-cwd.ps1` and `revision`.
Profiles remain your explicit wiring; deploy never edits them. These exact profile
lines honor `HERDR_APP_HOME`, defaulting to `~/.config/herdr-app`:

Bash profile:
```bash
_herdr_cwd_hook="${HERDR_APP_HOME:-$HOME/.config/herdr-app}/.customizations/runtime/shell/bash-cwd-loader.sh"; if [[ -r $_herdr_cwd_hook ]]; then source "$_herdr_cwd_hook"; fi; unset _herdr_cwd_hook
```

PowerShell profile:
```powershell
$herdrHome = if ($env:HERDR_APP_HOME) { $env:HERDR_APP_HOME } else { Join-Path $HOME '.config/herdr-app' }; $cwdHook = Join-Path $herdrHome '.customizations/runtime/shell/powershell-cwd.ps1'; if (Test-Path -LiteralPath $cwdHook -PathType Leaf) { . $cwdHook }; Remove-Variable cwdHook, herdrHome
```

Bash captures its loader directory at source time and reads its sibling payload
and deploy-owned content revision there, even after `cd`. Compatible payload
updates reload at the next idle prompt, preserving command status and existing
prompt hooks. Only interactive Herdr TTYs report; captured tool shells stay quiet.
PowerShell reports logical `Get-Location`, not Win32 process cwd.

After relocating an old loader, re-source only the installed loader **at an idle
prompt**, or open a new shell. Dispatcher structural changes also need this
explicit reload; a new revision refreshes compatible payload definitions, not
already-resident dispatcher code. Do not reload all of `.bashrc`, inject input or
restart agents. Install on every peer before changing dotfiles or deleting old
source. The optional private Claude shell initializer remains separately managed;
its own updates do not change this deploy-owned revision.

## Rollback / removal

Deploy reports a backup ID when it changes files. Ordinary rollback always requires
that ID and the stock layout; switch to Herdr/main first:

```powershell
npm run disable
node tools/rollback.mjs <backup-id>
```

Rollback refuses later personal edits or newer deployment records. Backups are
local and never committed. Do not restore entire live session documents.

`npm run remove` restores opted-in native exceptions and terminal key routing
before deleting owned files. Close Custom file/mod panes first. Modified personal
files and palette/preference data are retained; conflicts stop removal. Switching
layouts alone does not uninstall features or reset per-terminal preferences.
